# Alice 双权益套餐设计

## 目标

将一期套餐从内部的“任务额度”改为用户可理解、可承诺的两类独立权益：数据查询次数与调研报告次数。

## 已确认规则

- 基础版：¥199 / 月，80 次数据查询、8 次调研报告。
- 高级版：¥549 / 月，220 次数据查询、22 次调研报告。
- 权益独立发放、独立扣减，不互相兑换或透支。
- 当前界面仅为 mock；价格、折扣、周期及两类次数以后由后台配置提供。
- 一期不向用户展示 Linkfox 积分、“约可”或“任务额度”。
- 数据查询与调研报告的失败、超时、返还，都只影响对应权益。

## 体验与信息架构

### 套餐选择

套餐卡的“包含”区展示两行确定权益：

- `80 次数据查询`
- `8 次调研报告`

周付、月付、年付均展示对应的两类 mock 次数。选中卡片、折扣与支付流程沿用当前交互。

### 套餐与账单

顶部改为两张等权重的余额卡：数据查询余额与调研报告余额。每张卡显示剩余次数、已用 / 总次数及进度条；到期时间、续订、升级仍作为相邻操作区。

“额度明细”保留为一个垂直滚动列表，每次 mock 10 条。每条记录明确其权益类别和变动，例如：

- 数据查询｜标准数据查询｜消耗｜-1｜余额 65
- 调研报告｜竞品调研报告｜消耗｜-1｜余额 7

表格余额列由单一余额改为“该权益余额”，不出现跨权益合计余额。

### 余额不足

后续任务提交校验与提示都必须按实际能力类型判断：查询不足提示“数据查询次数不足”，报告不足提示“调研报告次数不足”。入口均前往现有套餐选择视图。

## 前端数据边界

新增 mock 套餐权益结构：

```ts
type PlanEntitlements = {
  dataQueries: number;
  researchReports: number;
};
```

当前激活套餐的余额以同样的两个字段表达。视图不计算 Linkfox 积分，也不将两种次数换算为统一余额。未来服务端只需返回该结构、有效期、明细列表与订单列表。

## 验收标准

- 所有面向用户的套餐、账单与明细文案中不再出现“任务额度”。
- 两档、三个付费周期均展示两类权益。
- 账单总览中可同时看见两类余额与独立进度。
- 明细能区分查询与报告，并在独立余额语义下展示。
- 既有选择套餐、支付二维码、订单记录交互不回归。
