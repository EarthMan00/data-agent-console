## 4. 问题清单

### P1-01 登录后未恢复用户原始目标路径

- 关联用例：ALICE-AUTH-001、ALICE-AUTH-005
- 影响模块：登录、受保护导航
- 复现路径：
  1. 清空浏览器登录态。
  2. 打开 `http://127.0.0.1:3000/`。
  3. 点击侧边栏 `提示词库`。
  4. 页面弹出登录框。
  5. 完成登录。
- 实际结果：
  - 登录成功后仍停留在首页 `/`。
  - 用户需要再次点击 `提示词库` 才能进入原本想访问的页面。
- 预期结果：
  - 登录成功后自动进入用户刚才点击的目标页，例如 `/prompt-library`。
  - 或在登录框内明确告知“登录后将继续访问提示词库”。
- 体验影响：
  - 登录打断后缺少任务恢复，用户会认为点击失效或路径丢失。
- 建议：
  - 在触发登录前保存 intended route。
  - 登录成功后优先跳转 intended route，消费后清空。

### P1-02 任务结果已出现，但页面仍显示处理中和停止任务

- 关联用例：ALICE-RUN-003、ALICE-RUN-004、ALICE-RUN-005
- 影响模块：首页任务执行、Agent 工作区、任务状态机
- 复现路径：
  1. 登录后进入首页。
  2. 从提示词库使用提示词：`体验测试-无线充电器市场分析-232636`。
  3. 点击提交按钮发起任务。
  4. 等待页面出现 `任务执行结果`、`收藏报告`、`数据报告`。
- 实际结果：
  - 右侧/主区域已经出现结果内容。
  - 页面仍显示类似 `表格处理中 · 已等待 0 分 32 秒`。
  - `停止任务` 按钮仍然可见。
  - 等待计时存在阶段切换后重置的体感。
- 预期结果：
  - 结果生成后任务状态应切换为完成。
  - `停止任务` 应隐藏或变成不可用。
  - 页面应明确给出完成态，例如 `任务已完成`、`查看报告`、`收藏报告`。
- 体验影响：
  - 用户无法判断任务到底完成还是仍在跑。
  - 结果已可见时仍允许停止，会造成误操作风险。
- 建议：
  - 统一 run 状态机，结果面板出现后同步完成态。
  - 停止按钮只在 running / queued 状态展示。
  - 将耗时计时从单阶段计时改为任务总耗时或清晰标注阶段耗时。

### P1-03 核心 E2E 用例全部失败，自动化测试与当前登录流脱节

- 关联用例：ALICE-ENG-003
- 影响模块：自动化测试、回归质量门禁
- 复现路径：
  1. 在仓库根目录执行：

```bash
npx playwright test tests/e2e/core-navigation.spec.ts tests/e2e/home-to-agent.spec.ts tests/e2e/templates-and-schedules.spec.ts --reporter=line
```

- 实际结果：
  - 3 个用例全部失败。
  - `core-navigation`：期望进入 `/prompt-library`，实际仍在 `/`。
  - `home-to-agent`：期望出现 `runId=`，实际未登录提交后仍在 `/`。
  - `templates-and-schedules`：直接访问受保护页面后找不到 `定时任务` 标题。
- 预期结果：
  - E2E 应显式处理登录态，或在测试 setup 中预置认证。
  - 未登录跳转、登录弹窗、登录后继续访问都应有稳定断言。
- 体验影响：
  - 自动化回归无法区分真实产品 bug 和测试脚本过期。
  - 后续前端改动缺少可信质量门禁。
- 建议：
  - 增加认证 fixture，覆盖已登录和未登录两组路径。
  - 将当前未登录保护逻辑更新进 E2E 预期。
  - 为登录后 intended route 增加专门回归用例。

### P1-05 浏览器运行时出现 useEffect 依赖数组长度变化错误

- 关联用例：ALICE-COMPOSER-001、ALICE-RUN-002
- 影响模块：任务输入框、工具 chip、React 运行时
- 复现路径：
  1. 进入首页。
  2. 从提示词库使用带 `@亚马逊前台` 的提示词。
  3. 在输入框中形成工具 chip 和提示词正文。
  4. 打开浏览器控制台。
- 实际结果：
  - 控制台出现错误：

```text
The final argument passed to useEffect changed size between renders. The order and size of this array must remain constant.
```

- 预期结果：
  - Hook dependency array 的长度和顺序在每次渲染中保持固定。
  - 控制台不应出现 React runtime error。
- 体验影响：
  - 这类错误可能导致编辑器同步、工具删除、焦点恢复等行为不稳定。
- 建议：
  - 检查 `TaskComposer` 相关 `useEffect`，避免条件性拼接 dependency array。
  - 将条件值转为稳定依赖，或拆分 effect。

### P2-03 定时任务提示词编辑器的可访问编辑语义不完整

- 关联用例：ALICE-SCHEDULE-001、ALICE-A11Y-002

  4. 尝试用标准自动化方式向 `role=textbox` 元素输入文本。
- 实际结果：
  - 外层元素暴露为 textbox，但不是标准 `input`、`textarea` 或 `contenteditable`。
  - Playwright 标准输入失败，需要用 JS 注入事件才能继续测试。
- 预期结果：
  - 编辑区应具备稳定的可编辑语义。

  - 这会降低键盘、读屏、自动化回归的可靠性。
- 建议：
  - 确认实际可编辑节点是否正确设置 `contenteditable` 和 ARIA 属性。
  - 将 `data-testid="task-composer-textbox"` 绑定到真正可编辑节点。

### P2-06 报告 iframe sandbox 配置触发安全警告

- 关联用例：ALICE-ARTIFACT-002、ALICE-ENG-002
- 影响模块：收藏报告详情、报告 iframe
- 复现路径：
  1. 打开收藏报告详情页。
  2. 查看浏览器控制台。
- 实际结果：
  - 控制台出现警告：

```text
An iframe which has both allow-scripts and allow-same-origin for its sandbox attribute can escape its sandboxing.
```

- 预期结果：
  - iframe sandbox 权限应最小化，并避免浏览器安全警告。
- 体验影响：
  - 对内嵌 HTML 报告而言，这是潜在安全边界问题。
- 建议：
  - 评估报告 iframe 是否必须同时开启 `allow-scripts` 和 `allow-same-origin`。
  - 如果只是展示静态报告，优先移除脚本执行权限。
