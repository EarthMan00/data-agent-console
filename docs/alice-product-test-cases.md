# Alice 主产品测试用例

## 1. 范围

本文档覆盖 Alice 前台主产品链路：

- 首页：`/`
- 会话执行页：`/agent`、`/?runId=...`
- 指令库：`/prompt-library`
- 定时任务：`/schedules`
- 收藏夹/产物：`/artifacts`
- 结果页：`/report`
- 分享页：`/share/[shareId]`
- 登录弹窗与登录后续发链路

不覆盖后台管理页、运营配置页、服务端任务编排正确性本身；但当服务端状态影响前端体验时，前端应给出可理解的状态、恢复入口或降级提示。

## 2. 优先级定义

- `P0`：主价值链路阻塞，失败不可发布。
- `P1`：高频关键体验或闭环断点，失败需尽快修复。
- `P2`：边界、空态、可访问性、文案和一致性问题。

## 3. 测试前置条件

- 本地服务可访问：`http://127.0.0.1:3000`
- 有可登录测试账号。
- 浏览器控制台无初始阻塞级错误。
- 测试时记录：
  - 当前 URL
  - 截图
  - 控制台错误
  - 关键接口错误状态码
  - 任务 `runId` 或 `sessionId`

## 4. 测试数据

- 任务目标 A：`帮我分析美国亚马逊无线充电器市场，找出热销产品、价格区间和机会点。`
- 任务目标 B：`请分析美国站 keyboard tablet case 赛道，并输出机会点。`
- 指令标题：`体验测试-无线充电器市场分析`
- 指令内容：`@亚马逊前台 帮我分析美国亚马逊无线充电器市场，输出热销产品、价格带和差异化机会。`
- 定时任务标题：`体验测试-每日无线充电器市场监控`
- 不存在搜索词：`zzzz-no-result-20260620`

## 5. 登录与权限

### ALICE-AUTH-001 未登录访问首页

- 优先级：`P0`
- 类型：手工 + E2E
- 前置条件：退出登录或清空登录态
- 步骤：
  1. 打开 `/`。
  2. 查看首页是否完整展示。
  3. 点击左侧导航的指令库、定时任务、收藏夹。
- 预期结果：
  - 首页可正常展示。
  - 受保护页面触发登录要求或回到明确登录入口。
  - 不出现白屏、死循环跳转、无解释空白页。

### ALICE-AUTH-002 未登录发起任务触发登录

- 优先级：`P0`
- 类型：手工 + E2E
- 前置条件：未登录
- 步骤：
  1. 打开 `/`。
  2. 输入任务目标 A。
  3. 点击发送。
- 预期结果：
  - 出现登录弹窗。
  - 弹窗说明为什么需要登录。
  - 用户已输入的任务目标不丢失。

### ALICE-AUTH-003 登录成功后继续发送任务

- 优先级：`P0`
- 类型：手工 + E2E
- 前置条件：未登录，已通过 `ALICE-AUTH-002` 打开登录弹窗
- 步骤：
  1. 输入正确测试账号。
  2. 登录成功。
  3. 观察弹窗、首页输入框和页面跳转。
- 预期结果：
  - 登录弹窗关闭。
  - 登录前输入的任务自动继续发送，或出现明确的「继续发送」按钮。
  - 成功进入任务执行态，URL 出现 `runId` 或进入 `/agent`。
  - 不要求用户重新输入任务。

### ALICE-AUTH-004 登录失败提示

- 优先级：`P1`
- 类型：手工 + E2E
- 前置条件：未登录
- 步骤：
  1. 打开登录弹窗。
  2. 输入错误密码。
  3. 提交。
- 预期结果：
  - 停留在登录弹窗。
  - 显示明确错误提示。
  - 密码输入框不明文展示。
  - 不清空账号字段。

### ALICE-AUTH-005 已登录访问受保护页面

- 优先级：`P0`
- 类型：手工 + E2E
- 前置条件：已登录
- 步骤：
  1. 直接访问 `/prompt-library`。
  2. 直接访问 `/schedules`。
  3. 直接访问 `/artifacts`。
- 预期结果：
  - 页面均可访问。
  - 左侧账号区域显示登录态。
  - 不被错误重定向到首页或登录弹窗。

## 7. 任务执行与会话页

### ALICE-RUN-001 新任务进入执行页

- 优先级：`P0`
- 类型：手工 + E2E
- 前置条件：已登录
- 步骤：
  1. 从首页提交任务目标 A。
  2. 等待页面进入任务页。
  3. 查看顶部用户输入卡。
- 预期结果：
  - 用户输入卡显示完整任务目标。
  - 页面出现任务拆分或执行进度。
  - 不出现旧任务详情区、空白执行区。

### ALICE-RUN-002 任务拆分展示

- 优先级：`P0`
- 类型：手工
- 前置条件：任务已进入执行态
- 步骤：
  1. 查看「任务拆分」区域。
  2. 观察步骤标题和状态。
- 预期结果：
  - 任务拆分作为独立内容块展示。
  - 每个步骤有可读名称。
  - 不把任务拆分塞进任务执行卡内部。

### ALICE-RUN-003 执行进度可理解

- 优先级：`P0`
- 类型：手工
- 前置条件：任务执行中
- 步骤：
  1. 查看任务执行状态。
  2. 等待 60 秒。
  3. 查看状态变化。
- 预期结果：
  - 当前步骤、总步骤、执行中/等待/完成状态清楚。
  - 超过合理时间仍等待时，出现排队、慢任务或后台执行提示。
  - 有重试、停止或继续等待的明确入口。

### ALICE-RUN-004 执行结果与状态一致

- 优先级：`P0`
- 类型：手工 + 回归
- 前置条件：有任务产生表格或其他结果
- 步骤：
  1. 打开对应任务。
  2. 查看步骤状态。
  3. 查看右侧或下方结果区。
- 预期结果：
  - 如果步骤失败，不应同时无解释地展示可下载结果。
  - 如果有部分结果，应标记「部分完成」或「部分结果可用」。
  - 如果用户停止任务，应标记「已终止」，不要误写成普通失败。

### ALICE-RUN-005 停止任务

- 优先级：`P1`
- 类型：手工 + E2E
- 前置条件：任务执行中
- 步骤：
  1. 点击「停止任务」。
  2. 确认停止。
  3. 查看状态和已产出结果。
- 预期结果：
  - 停止后状态为「已终止」或等价表达。
  - 已产出的结果如果可用，应保留并说明。
  - 不应仅显示「任务执行失败」而不说明原因。

### ALICE-RUN-006 工具卡标题

- 优先级：`P1`
- 类型：手工
- 前置条件：任务执行区存在工具卡
- 步骤：
  1. 查看工具卡标题。
  2. 点击查看。
- 预期结果：
  - 标题使用具体数据源或动作名称。
  - 不使用泛化的「调用工具」。
  - 点击查看后结果预览正确切换。

### ALICE-RUN-007 继续追问

- 优先级：`P1`
- 类型：手工
- 前置条件：任务已有结果或部分结果
- 步骤：
  1. 在底部输入器输入追问：`请只保留价格在 20-40 美元的产品。`
  2. 点击发送。
- 预期结果：
  - 追问进入同一会话上下文。
  - 不创建无关新任务。
  - 页面滚动和输入器位置稳定。

### ALICE-RUN-008 异常任务恢复入口

- 优先级：`P1`
- 类型：手工
- 前置条件：任务失败、超时或接口报错
- 步骤：
  1. 打开失败任务。
  2. 查看错误提示。
- 预期结果：
  - 错误原因面向用户可理解。
  - 至少提供重试、复制任务、重新发起或联系支持入口之一。
